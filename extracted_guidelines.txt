1. PROJECT OVERVIEW & OBJECTIVES
The BBAT104 Course Project is an integrated software development and quality audit task. Every student is assigned a baseline system based on their Roll Number, along with a sequentially assigned Quality Goal (Q01 to Q20) within each project group. This structure yields up to 180 unique project combinations to guarantee individual accountability and deep hands-on application of Total Quality Management (TQM) principles.
2. ASSIGNMENT RULES & TOPIC MAPPING MATRIX
• Baseline Software System Assignment Rule: Assigned based on the last digit of the Roll Number, For a batch size of 200 students, the class is divided across 10 core baseline software topics (forming 10 working groups of approximately 20 students each). Every student within a group works on the assigned baseline system while implementing their unique sequential Quality Goal (Q01-Q20) on sequential basis.

6. REQUIRED TOOLS, SOFTWARE DEPENDENCIES, TQM PRINCIPLES & SQC TOOLS
6.1 Development Tools & Software Dependencies
• Visual Studio / Visual Studio Code: Primary Integrated Development Environment (IDE) used for writing, debugging, and managing source code.• GitHub Account: Cloud repository platform for hosting project source code, version history, and submitting progress links.• GitHub Desktop: GUI client used to sync local code commits, track version changes, and manage repository pushes/pulls.• Python & Core Dependencies: Python 3.x core runtime alongside standard/third-party libraries: Tkinter/CustomTkinter (GUI interfaces), SQLite3/Pandas (Data persistence & storage), and Matplotlib/Seaborn (Automated generation of SQC charts).
6.2 Core TQM Principles Applied
• Customer Focus: Designing system features specifically to solve user operational pain points.• Continuous Improvement (Kaizen): Iteratively refining software features through systematic PDCA feedback cycles.• Process-Centric Approach: Mapping software inputs and outputs explicitly through structured SIPOC diagrams.• Fact-Based Decision Making: Utilizing empirical defect tracking metrics to target bug fixes.• Error Prevention (Poka-Yoke): Embedding strict input validation and field masks to eliminate errors at the entry level.
6.3 Statistical Quality Control (SQC) Tools Requirements
• Pareto Analysis (80/20 Rule): Charting defect frequencies to isolate the vital 20% causes driving 80% of system errors.• Ishikawa (Fishbone) Diagram: Categorizing root causes across People, Process, Software Code, and Infrastructure.• Checksheets & Defect Logs: Standardized logging matrices for tracking defect occurrence, severity, and resolution status.• FMEA Matrix: Calculating Risk Priority Numbers (RPN = Severity × Occurrence × Detection) to prioritize fixes.
7. STEP-BY-STEP PROJECT EXECUTION PROCESS
• Step 1: Environment Setup & Repository Initialization: Install Python 3.x, Visual Studio Code, and GitHub Desktop. Create a public GitHub repository named 'BBAT104_TQM_[RegNo]' and commit an initial README.md containing project details.
• Step 2: Requirement Analysis & SRS Documentation: Identify assigned baseline system from Roll No digit. Draw a System Architecture Flowchart, establish Critical to Quality (CTQ) parameters, and prepare the SRS document.
• Step 3: Base System & CRUD Development: Develop the base application in VS Code using Python. Implement core CRUD (Create, Read, Update, Delete) operations connected to SQLite or file storage.
• Step 4: Integration of Assigned Quality Goal Features: Select any 5 features from your assigned Quality Goal (Q01–Q20). Program and integrate these specialized modules into your base application.
• Step 5: Process Mapping & Risk Audit (FMEA): Construct a SIPOC diagram mapping input-output flows. Build an FMEA matrix identifying failure modes, calculating RPN scores, and defining mitigation steps.
• Step 6: Statistical Quality Control (SQC) & Continuous Improvement: Log software bugs on a Checksheet. Generate Pareto Charts and Fishbone Diagrams in Python/Matplotlib. Execute the Plan-Do-Check-Act (PDCA) cycle.
• Step 7: GitHub Version Control Sync & Documentation: Commit code changes regularly via GitHub Desktop (minimum 30 commits). Update README.md with system architecture diagrams, user manuals, and setup instructions.
• Step 8: Final Review Submission & Viva Defense: Submit the completed repository link. Deliver a live software demonstration showing feature execution and defend TQM tool selections during oral viva.
