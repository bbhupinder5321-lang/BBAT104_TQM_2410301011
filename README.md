## Project Overview

A desktop Hospital Management System developed for BBAT104 – Fundamentals of TQM.

The application combines practical hospital workflows with **Q02 – Improve Performance** quality improvements.

The project is designed around a simple layered architecture:

**GUI → Service → Repository → SQLite**

- **GUI** shows information and collects user actions.
- **Service** contains validation and business rules.
- **Repository** performs database queries.
- **SQLite** stores application data.

## Assigned System

**Baseline System:** Hospital Management System  
**Core TQM Goal:** Reduce patient waiting time and prevent record duplication.  
**Assigned Quality Goal:** **Q02 – Improve Performance**

## Q02 Performance Features

### 1. Fast Search
Patients can be searched by name, phone or patient ID.

### 2. Optimized Reports
The reporting module uses focused SQL queries for patient, doctor, appointment, billing, waiting-time and recent-patient reports.

### 3. Performance Dashboard
The dashboard provides:
- Today's patients
- Today's appointments
- Pending appointments
- Bed occupancy
- Average patient waiting time
- Patient/appointment activity
- Q02 performance features

The dashboard also includes lightweight UI animations and interactive navigation.

### 4. CSV Import
Bulk patient records can be imported using CSV processing with validation and duplicate protection.

### 5. Efficient Database Queries
SQLite indexes are maintained for frequently queried patient, appointment, billing and doctor fields.

## Waiting-Time Measurement

For an appointment:

**Waiting time = Consultation Start Time − Check-in Time**

The appointment module records both timestamps. The dashboard calculates the average from valid timestamp pairs.

No artificial waiting-time values are generated by the dashboard.
